    ===================================================================================================

    기초 잡아둔 거 설정 완료하면 보통 M T V 순서로 코드 작성. 모델 -> 템플릿(HTML, 안드로이드의 뷰) -> 뷰 (안드로이드의 뷰모델, 세부항목정렬)
    순서는 models.py 의 테이블 설정 -> admin.py 관리자페이지에서 보여줄 데이터 리스트 선별 ->
    apps/services 패키지 생성 후 ai엔진테스트 파일 생성, -> 템플릿에 index.html 생성 ->
    views.py에 세부규칙 지정(함수) -> views.py의 함수 기반으로 urls.py에 경로 지정 ->
    core/urls.py 에 path('tracker/', include('apps.tracker.urls')) 한줄만 추가해주면 알아서 앱경로위치의 경로를 체크함!
    앱경로에 쓰지않고 코어경로에 바로 써도 되지만 굳이 2곳에 같이 쓸 필요 없고 기능이 많은 경우는 인클루드사용해서 하나만 쓰기.

    Model (models.py): DB 설계. (안드로이드의 Room Entity 정의)
    Admin (admin.py): 관리자 페이지 등록. (DB에 데이터 잘 들어갔나 확인용 도구)
    Engine (services/ai_engine.py): 손동작 분석 로직. (안드로이드의 UseCase나 Service 레이어)
    Template (index.html): 화면 UI. (안드로이드의 activity_main.xml)
    View (views.py): 비즈니스 로직 및 데이터 바인딩. (안드로이드의 ViewModel + Activity 로직)
    App URL (앱이름/urls.py): 앱 내부 경로 지정. (특정 화면들로 가는 네비게이션 정의)
    Core URL (core/urls.py): 프로젝트 전체의 이정표.

    안드와 비교했을때

    Model (models.py) <-> Room Entity / Data Class:
    데이터를 저장할 테이블 구조를 설계하는 단계입니다.
    안드로이드에서 SQLite나 Room DB를 쓸 때 데이터 테이블(Entity)을 정의하는 것과 똑같은 기초 공사입니다.

    Admin (admin.py) <-> Database Inspector / Debug Tool:
    DB에 데이터가 잘 쌓이고 있는지 눈으로 직접 확인하기 위한 관리자 페이지 설정입니다.
    안드로이드 스튜디오에서 DB 내부를 들여다보는 도구와 비슷한 역할을 수행합니다.

    Engine (services/ai_engine.py) <-> UseCase / Repository / Library:
    미디어파이프를 이용한 손동작 분석처럼 순수한 계산 로직이 들어가는 레이어입니다.
    안드로이드에서 비즈니스 로직을 처리하는 서비스나 유즈케이스 계층에 해당합니다.

    Template (index.html) <-> activity_main.xml (Layout):
    사용자에게 보여질 실제 화면 UI를 만드는 단계입니다.
    안드로이드에서 XML 파일로 버튼이나 텍스트 뷰를 배치하는 작업과 완벽히 대칭됩니다.

    View (views.py) <-> ViewModel + Activity Logic:
    데이터를 가공하고 화면(HTML)에 꽂아주는 핵심 로직입니다.
    안드로이드에서 뷰모델(VM)이 데이터를 처리하고 액티비티가 이를 UI에 바인딩하는 역할을 동시에 수행한다고 보시면 됩니다.

    App URL (앱이름/urls.py) <-> Navigation Graph (Fragment 단위):
    특정 앱 내부에서 화면들이 어떻게 전환될지 경로를 지정하는 단계입니다.
    안드로이드에서 프래그먼트 간의 이동 경로를 설정하는 네비게이션 그래프와 비슷합니다.

    Core URL (core/urls.py) <-> AndroidManifest.xml / Deep Link:
    프로젝트 전체의 입구를 결정하는 이정표입니다.
    안드로이드에서 앱의 진입점(Main Activity)을 설정하거나 외부 딥링크 주소를 정의하는 매니페스트 파일과 같은 역할을 합니다.
