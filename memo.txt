서버 ai 방식이 아닌 클라이언트 중심의 온디바이스 ai 구조로 진행 예정.
백엔드 중점은 서버 형태지만 온디바이스 형태가 속도부터 서버비용, 편리함 등등 ux면으로 편하고 보안도 챙김

대신 백엔드로는
1. 데이터 구조 설계 (Data Architecture)
MediaPipe가 뱉어낸 21개의 복잡한 좌표 데이터를 어떻게 효율적으로 DB에 저장하고 관리할 것인가?
3D 포즈를 재현하기 위한 JSON 규격 설계 능력을 보여줄 수 있습니다.

2. 비즈니스 로직의 API화
사용자가 만든 포즈를 저장, 수정, 공유하는 REST API를 탄탄하게 구축합니다.
클라이언트에서 계산된 결과값이 유효한지 검증(Validation)하는 로직을 서버에 배치하여 데이터 신뢰성을 확보합니다.

3. 결과물 관리 (Storage & Serving)
수많은 사용자의 포즈 데이터를 빠르게 조회하기 위한 인덱싱 처리나, 통계 데이터를 뽑아내는 쿼리 최적화 실력을 보여줍니다.

위주로 진행, "AI 연산은 온디바이스로 처리하여 성능을 극대화하고,
백엔드(Django)는 이 데이터를 체계적으로 관리하고 서비스화하는 API Hub 역할을 수행하도록 설계했습니다."
